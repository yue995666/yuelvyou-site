## 1. 产品定位与最小核心体验

用户每天打开工作台，应能迅速回答四个问题：**今天找谁聊？为什么找？上次聊到哪里？下一句怎么回复？**

尽量保持 **4 个一级模块**：今日工作台、我的客户、聊天助手、跟进计划。首页强调可执行的客户行动卡片，避免增加不必要的统计图表与复杂 CRM 流程。现有旅行网站其他页面属于独立项目，修改 `sales/` 不得影响根目录首页及 `/dayueyue/`。

### UI 设计约束

- 沿用已经选定的**海景蓝白、温暖轻盈**视觉风格：浅色背景、蓝色主按钮、圆角卡片、清晰中文、适量旅行氛围。
- 一眼能看见联系对象、联系原因、上次聊天要点与参考回复；次要信息按需展开。
- 桌面和手机端都应可用；按钮必须真的能执行操作，不能只放静态 UI。
- 不得把设计参考图上的日期、任务数和成交数据作为真实生产数据。

## 2. 当前线上功能与如实标注

**目前是无账号的静态公开体验版，并非已实现云端 CRM。**

| 能力 | 当前状态 |
| --- | --- |
| 今日客户建议、客户档案、跟进任务 | 已有浏览器端交互 |
| 聊天文本分析与建议回复 | **本地规则**，不是真正接入在线大模型的 AI |
| 微信截图 | 本地预览；**没有自动 OCR 识别** |
| 资料保存 | 当前浏览器的 **localStorage**，清理数据可能丢失；请导出备份 |
| 注册登录、云端同步、跨设备访问 | **尚未实现** |
| 多用户账号及服务端权限隔离 | **尚未实现**；不能将本地数据模式误称为多租户安全系统 |

添加任何新能力时，必须先完成实现与测试，再更新本表；不得提前把规划中的能力写成“已上线”。

## 3. 数据、隐私与版权红线（强制）

1. **此 GitHub 仓库公开**：仅允许虚构的示例客户与不含敏感内容的测试数据。禁止上传真实客户姓名/微信号、聊天截图、个人销售复盘原文、客户待核对 JSON、付费老师的课程原文、账号密码、API 密钥、令牌或包含上述内容的 ZIP/备份。
2. 真实客户资料必须保存在授权的私人数据空间；将来做多账号服务时，必须服务端鉴权、逐用户数据隔离、可导出与可删除。禁止通过前端隐藏字段模拟权限。
3. 未明确获得授权的老师课程案例不能随公开网站分发；可在合规前提下提炼通用方法，但不得擅自公开课程全文。
4. 客户分析必须区分 **客户原话／本人复盘／系统推测／未知信息**。没有记录就写“未知”，不得编造职业、收入、对话内容或已付款事实。
5. **“注册游客”不等于“购买398元会员”**，“介绍过产品”不等于“有购买意愿”。不许把示例或推测计入真实销售业绩。
6. 客户明确拒绝某项营销时，停止该类别的推销建议；不得因为时间过去就自动反复营销。不得编造收益保证、固定返佣、会员费抵扣权益，或承诺必得0元机票。
7. 引入外部 AI 服务前，必须告知用户上传内容将如何处理，明确授权、访问控制、密钥存放和隐私政策；**API 密钥只能放服务端**。

## 4. Git 改动与提交规范（必须执行）

每次修改遵守以下流程，**缺一项不得标记为正式交付**：

1. **检查现状**：明确要修改的页面、代码及现有测试；记录当前 commit 与预期行为。
2. **实施最小改动**：不要覆盖既有版本、私人数据或其他站点；不得为了新增功能顺手重写无关模块。
3. **同时增加或更新对应测试**：新功能有新测试；Bug 修复有回归测试；README/约束变更要更新文档契约测试。
4. **本地全部验证**：运行 `python -m pytest -q sales/tests`；检查浏览器控制台报错、移动端、隐私扫描；公开页面如涉及更新，还要确认主要交互正常。
5. **全部通过才提交**：每个逻辑改动创建对应 **Git commit**，信息应能说明范围及目的，例如 `docs(sales): codify release and privacy rules` 或 `fix(sales): stop promotion after opt-out`。
6. **提交后检查**：核对远程 commit SHA、文件确实已提交、部署路径未被破坏；验证实际 URL 可打开才能宣称线上生效。
7. **交付报告**：必须附改动内容、commit SHA/链接、测试命令、通过数量、线上访问验证情况、已知限制及回滚办法。

若测试失败、缺少密钥、没有 Git 提交权限或不能验证线上部署，**必须明确披露并停止宣称“已完成全部测试/已上线”**。严禁虚构提交、测试或部署结果。

## 5. 验证命令与测试范围

从仓库根目录执行：

```bash
python -m pip install pytest playwright
# 根据运行环境安装 Chromium；若使用 Playwright 下载版：
python -m playwright install chromium
python -m pytest -q sales/tests
```

现有浏览器测试使用 `/usr/bin/chromium`；其他环境运行时需配置对应 Chromium 路径，不能因为依赖没装就当测试通过。浏览器不具备时可以运行文档静态检查，但**静态检查不能替代完整功能测试**。

需要覆盖：页面加载、客户新增与持久化、搜索/编辑、客户拒绝后的禁止营销、任务创建/完成、手机端导航、公开版无真实客户资料、README 的核心约束。新增功能必须扩充自动化测试；重大交互修改还应进行人工验收。每次代码提交不得删除/绕过失败测试以获得绿色结果。

## 7. 发布、备份与回滚

- 公开体验版发布到 `https://yuelvyou.cn/sales/`；先验证 Git 提交成功，再确认页面实际部署成功。
- **不要**把私人客户版本或含私人复盘的源代码包部署到公开路径。
- 浏览器本地存储并不等于云端备份；用户应从应用内导出数据，谨慎清理浏览器缓存。
- 若一次改动导致问题，优先使用 `git revert <commit-sha>` 创建回滚提交，再重新运行全部测试并验证站点；不要随意强制重置公共分支。
